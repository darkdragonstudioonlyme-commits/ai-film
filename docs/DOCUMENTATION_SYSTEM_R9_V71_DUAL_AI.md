## Compatibility and operational limits

Frozen product contracts and existing learning metrics remain unchanged. The old
one-chat mode discipline becomes one user-facing coordinator with bounded worker
sessions, not two competing master states. WORKFLOW_ROUTER remains the router;
transport states are subordinate receipts, not another workflow authority.

The V70 feasibility supplement remains a product design candidate, not accepted by
this documentation change. Its acyclic authority, cross-host locator and guard/
publication witness still need their own design/test review before affected dev23.

Observed capability check found no Claude executable in PATH or four usual Linux
locations. Plugin lookup returned no Claude/Anthropic connector. This does not inspect
all disks or infer account status. No credential file was read. Authentication,
model identity, usage consent and runtime isolation were not verified.

The headless plan differentiates subscriptions from separately billed API credentials.
A provider's bare mode can disable automatic policy loading; the trusted bundle must
therefore explicitly include policy and lessons. There is no promise that ChatGPT
continues outside its turn. Future asynchronous services are explicitly not deployed.

## Bootstrap circularity correction

An automatic dispatcher cannot require its own already-accepted deployment to obtain
the first non-author policy review. A narrowly user-authorized one-off tool-less vendor
CLI review can supply that evidence after real account/data/budget setup. It does not
execute candidate dispatcher code or grant ongoing automation. No self-audit is used
as a substitute for the other model and no safety denial is bypassed.
