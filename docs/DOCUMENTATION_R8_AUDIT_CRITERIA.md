# Documentation R8 holistic audit criteria

Audit the entire active control plane, not only changed files. Confirm:

- no duplicate-run risk, stale version ownership, conflicting state authority or post-timeout replay ambiguity;
- standing documentation governance policy does not pin one release's branch/worktree names; active identities are selected by canonical governance state;
- exact promotion-ready `PROJECT_STATE`/checkpoint predeclare final review/audit IDs and record paths, and post-audit promotion allows no other state/policy/checkpoint mutation;
- self-learning has canonical activation closure and does not count reviewed-but-unpromoted corrections as applied;
- learned-but-not-active backlog/activation lag are observable workflow-health concerns;
- source durability, source visibility and review authority remain distinct; partial source snapshots cannot masquerade as a full exact Git mirror;
- governance/checker logic rejects stale fixed documentation lane identities and missing promotion/activation/source-visibility fields;
- R8 incorporates useful R7 checker lessons without treating unpromoted R7 as active policy;
- policy growth does not create duplicate canonical owners or circular trust;
- final promotion does not alter Phase00 source behavior, convert dev20 producer output into reviewed/gate authority, or change native Windows/WSL/LAB/SITE status.
